# 기존 프로젝트 분석·디버깅

기존 파일을 먼저 읽고 구조, 진입점, 실행 명령, 의존성, 테스트 방법을 파악해줘.
1. 오류를 재현할 수 있는 최소 실행 또는 테스트를 수행한다.
2. 오류 메시지와 발생 위치를 근거로 원인을 좁힌다.
3. 원인과 수정 계획을 먼저 설명한다.
4. 변경 범위를 최소화하고 기존 기능을 보존한다.
5. 수정 후 관련 테스트와 회귀 테스트를 실행한다.
6. 변경 파일·이유·테스트 결과·남은 위험을 요약한다.

근거 없이 전체 구조를 재작성하거나 패키지를 대량 교체하지 마. 환경·네트워크·권한 문제와 코드 결함을 구분해줘.
